## 1. 产品目标与使用场景

### 1.1 产品目标

用一句话说：**玩家把自己的 Steam 主页地址粘进去，点一个按钮，由随机抽签决定今晚玩哪款游戏。**

具体目标：

1. 用户只需提供 SteamID64 或 Steam 个人资料地址，即可自动读取其游戏库，无需登录账号。
2. 点击“抽签”后播放约 1.8 秒的滚动减速动画，最终随机选中一款游戏。
3. 展示所选游戏的封面、简介、类型、发行日期、评分与售价。
4. 在 Windows 上提供极简的安装与使用体验：单个安装包、双击安装、桌面快捷方式。
5. 全中文界面，任何失败都给出能看懂的中文说明，不出现英文报错或程序崩溃。

### 1.2 非目标（明确不做）

- 不涉及游戏的购买、下载、启动（见 D1）。
- 不要求用户登录 Steam 账号，仅通过公开 Web API 读取公开数据。
- 不支持 macOS / Linux，第一版仅 Windows 10/11 64 位。
- 不做社交、分享、排行榜、成就等功能。

### 1.3 目标用户

- 拥有 Steam 账号、库中游戏较多（数十至上千款）的玩家。
- 面临“不知道玩什么”的选择困难，接受用随机化、游戏化的方式做决定。
- 电脑操作熟练度一般，期望安装简单、界面直观、不需要看说明书。

### 1.4 典型使用场景

**场景一：首次使用**
1. 下载并运行安装包，按向导完成安装，桌面出现快捷方式。
2. 首次启动，程序发现未配置 API Key，弹出引导窗口，说明去哪里申请。
3. 用户点击链接前往 Steam 开发者页面申请 Key，粘贴回程序并保存。
4. 粘贴自己的 Steam 个人资料地址，点击“加载游戏库”。
5. 程序读取游戏库并显示“已加载 128 款 · 96 款参与抽签”。

**场景二：日常抽签**
1. 打开程序，游戏库自动从缓存恢复，窗口瞬时可用。
2. 若想要更精准的范围，点开范围设置，切换“从未玩过”，或手动取消勾选。
3. 点击“抽签”，游戏名快速滚动约 1.8 秒后定格并变绿加粗。
4. 下方显示选中游戏的封面与详细信息。
5. 不满意就点“再抽一次”；满意就关掉程序去玩。

**场景三：离线 / 网络异常**
1. 断网状态下打开程序，使用上次缓存的游戏库，顶部显示黄色提示“当前离线，正在使用 09-19 15:04 缓存的数据”。
2. 抽签功能完全可用。
3. 详情区因无法联网，只显示游戏名 + “无法获取详情（可稍后重试）”，不影响继续抽签。

**场景四：失败提示**
1. 用户把 Steam 个人资料设为私密后再次加载。
2. 程序明确提示“无法读取游戏库，请将 Steam 个人资料和游戏详情设为公开”，而不是含糊地说“库为空”。

## 2. 整体页面框架与导航结构

### 2.1 界面清单

| 编号 | 界面 | 类型 | 用途 |
| :--- | :--- | :--- | :--- |
| W1 | 主窗口 | 唯一主窗 | 承载身份输入、库与范围、抽签、结果展示全部主流程 |
| W2 | 设置窗口 | `Toplevel` | 修改 API Key、快捷范围阈值、缓存有效期，打开日志目录 |
| W3 | 首次运行引导 | W2 的「首次模式」 | 同一窗口、只显示 Key 相关部分与一段说明，避免两套代码 |
| W4 | 关于 / 帮助 | `Toplevel` | 版本号、日志路径、隐私说明（Key 仅存本地、不上传） |
| W5 | 状态行 | 主窗内嵌区域 | 承载绝大多数成功 / 失败提示，不打断用户操作 |
| W6 | 确认对话框 | `messagebox` | 仅用于“需要用户做决定”的场景（配置损坏重置提示、卸载是否保留配置等） |

**交互原则：能用内嵌状态行（W5）说清的事情，绝不弹窗。**

### 2.2 导航结构

```
启动
 └─ 读 config.json
     ├─ 无 API Key ──────────────► W3 首次运行引导 ──保存──► W1 就绪
     └─ 有 API Key ──────────────► W1 主窗口
                                     ├─[设置]────────► W2 设置窗口
                                     ├─[关于]────────► W4 关于/帮助
                                     └─[去设置] ─────► W2 设置窗口

W1 是唯一常驻窗口；W2/W3/W4 均为依附于 W1 的 Toplevel，
关闭 W1 即结束程序；W2/W4 打开时 W1 仍可见。
W5 随 W1 常驻，不单独弹出。W6 仅按需弹出。
```

### 2.3 窗口规格与缩放规则

- 主窗口默认 800 × 600，可缩放，最小 640 × 480；设置窗口 420 × 300，不可缩放。
- 竖向缩放：只有“库与范围”区的列表吸收多余高度，其余分区保持定高；窗口高度不足 520 时该区自动收起。
- 横向缩放：结果区封面宽度 = `min(300, 可用宽度 × 0.30)`，保持 460 : 215 原图比例，最小 240 × 112（0.30 使默认 800 宽窗口正好落在 240，给新增的卡片留出高度）。
- 布局使用 Tkinter `grid`，各行 `weight` 明确，不混用 `pack` 造成的对齐问题。
- 字体：微软雅黑。

## 5. 每个模块第一版最必要的数据与操作

> 原则：**第一版只保留不可或缺的字段和动作**，其余一律不做。

### 5.1 区0 顶栏

| 数据 | 来源 | 持久化 |
| :--- | :--- | :--- |
| 应用版本号 | 代码常量 | 否 |

| 操作 | 触发 | 结果 |
| :--- | :--- | :--- |
| 打开设置 | 点 `[设置]` | 打开 W2 |
| 打开关于 | 点 `[关于]` | 打开 W4，显示版本与日志目录按钮 |

### 5.2 区1 身份输入

| 数据 | 来源 | 持久化 |
| :--- | :--- | :--- |
| 原始输入文本 | 用户输入 | 否 |
| 解析出的 SteamID64 | `ResolveVanityURL` 或直接截取 | 是，写入 `last_steam_id` |
| 状态行文案与颜色 | 程序状态 | 否 |

| 操作 | 触发 | 结果 |
| :--- | :--- | :--- |
| 加载游戏库 | 回车 / 点 `[加载游戏库]` | 解析身份 → 拉取游戏库 → 成功后进入 S3 |
| 刷新 | 点 `[刷新]` / `F5` | 忽略缓存，重新拉取当前 SteamID 的库 |
| 取消 | 加载中点 `[取消]` / `Esc` | 丢弃本次结果，回到上一个稳定状态 |
| 重试 | 状态行出现 `[重试]` 时点击 | 重放上一次失败的动作 |
| 去设置 | 状态行出现 `[去设置]` 时点击 | 打开 W2 |

**输入识别规则**（按顺序匹配）：

1. 17 位纯数字 → 直接作为 SteamID64。
2. 含 `/profiles/` → 取其后连续数字。
3. 含 `/id/` → 取其后到 `/` 或结尾的字符串，走自定义名解析。
4. 其余非空字符串 → 视为自定义名，走自定义名解析。
5. 空 → 提示“请先输入 Steam ID 或资料地址”。

### 5.3 区2 库与范围

| 数据 | 来源 | 持久化 |
| :--- | :--- | :--- |
| 游戏列表：`appid` / `name` / `playtime_forever` / `img_icon_url` | `GetOwnedGames` | 是，写入库快照缓存 |
| `excluded_appids` 排除集合 | 用户勾选 | 是，**唯一事实来源** |
| 当前预设 | 用户选择 | 是，仅用于回显 |
| 搜索关键词 | 用户输入 | 否 |
| 排序方式（游戏名 / 游玩时间，升或降） | 用户点击表头 | 是，写入 `ui` |

| 操作 | 触发 | 结果 |
| :--- | :--- | :--- |

## 6. 本地数据文件、备份与恢复要求

### 6.1 目录结构

```
%APPDATA%\SteamGamePicker\
├─ config.json                      主配置（含明文 API Key，见 D4）
├─ config.corrupt-YYYYMMDD-HHMMSS.json   配置损坏时的自动备份（只增不删最新 3 份）
├─ cache\
│  ├─ games_<steamid64>.json        游戏库快照
│  ├─ details\<appid>.json          单款游戏详情缓存
│  └─ img\<appid>.jpg               封面图缓存
└─ logs\
   └─ app.log                       运行日志（轮转）
```

### 6.2 `config.json` 字段

```json
{
  "schema_version": 1,
  "api_key": "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX",
  "last_steam_id": "76561198260031749",
  "excluded_appids": [123, 456],
  "last_preset": "never_played",
  "playtime_threshold_minutes": 120,
  "details_cache_ttl_days": 7,
  "language": "zh",
  "ui": {
    "pool_panel_expanded": true,
    "window_geometry": "800x600+120+80",
    "sort_key": "name",
    "sort_desc": false
  }
}
```

- 所有字段均可缺失，缺失时使用代码内默认值，**不得因缺字段而启动失败**。
- `api_key` 为空或缺失 → 进入 S0，弹出 W3 首次引导。

### 6.3 缓存文件

**库快照 `games_<steamid64>.json`**

```json
{
  "schema_version": 1,
  "steamid64": "76561198260031749",
  "updated_at": "2026-09-19T15:04:05+08:00",
  "games": [
    { "appid": 570, "name": "Dota 2", "playtime_forever": 1234, "img_icon_url": "abc" }
  ]
}
```

**详情缓存 `details\<appid>.json`**：仅保存界面需要的字段（`name` / `header_image` / `short_description` / `genres` / `release_date` / `metacritic_score` / `is_free` / `price_overview`）+ `cached_at`，不保存接口原始响应。

**封面缓存 `img\<appid>.jpg`**：与详情缓存同生命周期，详情过期时一并失效。

### 6.4 写入与容错要求

1. **原子写**：所有 JSON 一律“写临时文件 → `os.replace` 覆盖”，避免断电或强杀进程产生半截文件。
2. **损坏处理**：读取 `config.json` 若 JSON 解析失败或顶层不是对象 → 重命名为 `config.corrupt-<时间戳>.json`，按默认值启动，状态行黄字提示“配置文件已损坏，已备份并重置为默认设置”。程序**不得崩溃**。
3. **写入时机**：设置保存、加载成功后立即写；勾选变更做 1 秒防抖后写；窗口几何与折叠状态在退出时写。
4. **容量上限**：日志单文件 1 MB、保留 3 份；缓存总量上限 200 MB，超限按 `cached_at` 从旧到新清理。
5. **日志脱敏**：日志中**不得**出现完整 API Key（需要时只记录前 4 位 + `****`），不得记录完整请求 URL 中的 `key=` 参数。

### 6.5 备份、恢复与迁移

| 场景 | 要求 |
| :--- | :--- |
| 断网或接口失败但存在快照 | 使用最近一次快照进入 S7，黄条提示缓存时间；抽签可用，详情走失败降级 |
| 完全没有快照且加载失败 | 报错并提供 [重试]，不进入可抽签状态 |
| 缓存目录被手动删除 | 下次启动视为无缓存，重新拉取；不报错 |
| 缓存文件损坏 | 忽略该缓存并重新拉取，不打断使用（不弹窗） |
| 换机器 / 重装系统 | **整个 `%APPDATA%\SteamGamePicker` 目录可直接拷贝复用**（D4 明文存储的既定取舍）；第一版不提供图形化导入 / 导出 |
| 卸载 | 安装包卸载时询问“是否同时删除配置与缓存”，默认**保留**；选择保留则 `%APPDATA%` 数据不动 |

### 6.6 安全与隐私要求

- 仅访问 3 个 Steam 域名的 HTTPS 接口：`api.steampowered.com`、`store.steampowered.com`、`media.steampowered.com`（图片）。
- 不存储用户 Steam 密码，不上传任何用户数据，不含任何统计 / 埋点。
- API Key 不硬编码、不随安装包分发。
- 所有外部数据（游戏名、简介）均视为不可信文本，只做展示，不解析执行。

打包与安装要点：

### 7.4 线程与网络模型（强制）

1. **主线程只做 UI**，Tkinter 控件只在主线程被访问。
2. 所有网络请求（解析 ID、拉库、取详情、下图）在后台线程执行，结果经 `queue.Queue` 交回主线程，由 `root.after` 轮询消费。
3. 每次加载 / 抽签持有取消令牌；关窗、点取消、开始新一轮时，旧结果必须被丢弃且不能操作已销毁控件。
4. 请求超时 10 秒；对 429 / 5xx 做最多 2 次退避重试（1s、3s）。
5. 证书链校验失败（`SSLCertVerificationError`）时，若 `truststore` 可用则切换到操作系统信任库并**重试一次**（每个请求最多一次，见 D8）；切换失败或仍失败 → 提示"无法验证 Steam 服务器证书…"。断网、超时、协议错误**不得**触发该切换。
5. 抽签动画用 `root.after` 驱动，动画期间禁用输入与范围编辑；关窗前必须 `after_cancel`。

### 7.5 抽签算法与动画

- 候选池 = 当前已加载游戏 − `excluded_appids`；池为空时不启动动画，提示“当前范围内没有可抽签的游戏”。
- 中签结果在点击瞬间用均匀随机选定（`random.choice`），动画只负责表现，不得在动画结束时重新随机。
- 滚动过程中不连续显示同一名称（池中多于 1 款时）。

| 阶段 | 时间 | 间隔 | 说明 |
| :--- | :--- | :--- | :--- |
| 快滚 | 0 – 1200 ms | 固定 50 ms × 24 次 | 随机显示池内名称 |
| 减速 | 1200 – 1800 ms | 55 → 70 → 90 → 110 → 130 → 145 ms | 视觉减速 |
| 定格 | 1800 ms | — | 显示 winner，变绿加粗并做一次轻微放大回弹；同时发起详情请求 |

池中只有 1 款游戏时跳过滚动，直接做 300 ms 高亮定格。

### 7.6 Steam API 契约与已知行为

| 用途 | 接口 | Key |
| :--- | :--- | :--- |
| 解析自定义名 | `ISteamUser/ResolveVanityURL/v1/` | 是 |
| 获取游戏库 | `IPlayerService/GetOwnedGames/v1/?include_appinfo=true&include_played_free_games=true` | 是 |
| 获取详情 | `store.steampowered.com/api/appdetails?appids=<id>&cc=CN&l=schinese` | 否 |
| 封面/图标 | `media.steampowered.com/steamcommunity/public/images/apps/...` | 否 |

必须处理的已知行为：

1. **资料非公开不是错误码**：`GetOwnedGames` 对私密库返回 HTTP 200 且 `response` 中**没有** `games` 键。必须以此判定“资料非公开”，不得提示“库为空”。
2. `ResolveVanityURL` 未匹配时返回 `success: 42`（HTTP 200），需映射为“无法解析该资料地址”。
3. `appdetails` 返回结构为 `{"<appid>": {"success": bool, "data": {...}}}`；`success: false` 或缺少 `data` 时走详情降级。
4. 免费游戏没有 `price_overview`，需依据 `is_free` 显示“免费”；`metacritic` 常常缺失，显示 `—`。
5. 商店接口按 IP 限流（社区经验约 200 次 / 5 分钟），单次抽签只请求 1 次详情，命中缓存则不请求。

### 11.3 控件映射（确保 Tkinter 可实现）
