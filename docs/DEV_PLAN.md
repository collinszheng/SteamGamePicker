## 0. 使用说明

- 每个任务有唯一编号（`T<里程碑>.<序号>`），并绑定：**产出 / 完成定义（DoD）/ 对应验收编号（AC）**。
- 任务做完即回填第 11 章的进度表，并在 `docs/ACCEPTANCE.md` 记录该 AC 的实测证据。
- **任务只有同时满足第 7 章的 5 条统一 DoD 才算完成**，不靠"感觉做完了"。
- 任何与 PRD 冲突或 PRD 未描述清楚的实现选择，**先改 PRD 再改代码**，不允许静默新增决策。

## 2. 项目结构（M0 落地）

```
SteamGamePicker\
├─ main.py                      程序入口：初始化日志/配置 → 起主窗
├─ requirements.txt             requests, Pillow；（构建期）pyinstaller
├─ app\
│  ├─ errors.py                 错误枚举 + 中文文案（全项目唯一出处，对应 PRD 5.7）
│  ├─ config.py                 配置读写：原子写、损坏备份、字段缺省
│  ├─ models.py                 Game / GameDetails 数据结构
│  ├─ steamid.py                输入解析（纯函数，可单测）
│  ├─ pool.py                   预设计算、可抽池、均匀随机（纯函数，可单测）
│  ├─ steam_api.py              三个接口封装 + HTTP/业务错误分类
│  ├─ cache.py                  库快照、详情缓存、TTL、容量清理
│  ├─ images.py                 封面下载 + Pillow 缩放（按窗口宽度）
│  ├─ worker.py                 后台线程 + 队列 + after 轮询 + 取消令牌
│  ├─ logging_setup.py          轮转日志 + API Key 脱敏
│  └─ ui\
│     ├─ theme.py               字体、颜色、间距常量（对应 PRD 11.2）
│     ├─ main_window.py         区0–区4 与状态机 set_state()
│     ├─ settings_dialog.py     W2 设置窗 + W3 首次模式
│     └─ about_dialog.py        W4 关于窗
├─ assets\app.ico
├─ tests\                       纯逻辑单测 + HTTP 假响应 fixtures
├─ packaging\                   SteamGamePicker.spec、installer.iss
└─ docs\                        PRD.md、DEV_PLAN.md、ACCEPTANCE.md
```

**分层铁律**：`ui/` 可调 `worker/`；`worker/` 可调 `steam_api`、`cache`；但 `steam_api`、`cache`、`pool`、`steamid` **绝不 import 任何 tkinter**。这是"纯逻辑可单测"的前提，也是代码评审的硬性检查点。

    def cancel(self) -> None: ...
def submit(fn, on_done, on_error) -> Task
    # 结果经 queue.Queue，主线程 after(50ms) 消费；主线程不做任何网络调用

## 7. 每个任务的完成定义（统一 DoD 模板）

一个任务只有同时满足以下 5 条才算完成：

1. 代码写完且在本机跑通，无 `print` 调试残留；
2. 纯逻辑有单测，UI 有手工验证步骤记录；
3. 对应 AC 编号已实测通过并记录证据；
4. 与 PRD 无冲突；若发现 PRD 描述不清，**先改 PRD 再改代码**；
5. 未引入新的未记录决策（如 onefile / onedir 这类，必须写回 PRD）。
